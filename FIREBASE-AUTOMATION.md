# Firebase deployment automation
This workflow targets only the existing christmas-wishing-village project and default Firestore database. It does not deploy hosting, enable billing, create gameConfig, or delete student documents. Do not add --force: preserve indexes not present in the repo.
## One-time setup
1. In Firebase Console compare live Firestore Rules with the repository's rules, and verify any additional live protections are retained. The CLI replaces live rules with the repository file. Check live composite indexes too. If different, reconcile before deploying.
2. Use Google Cloud IAM to create a dedicated deploy service account, a GitHub OIDC workload identity pool/provider and grant that identity permission to impersonate the service account. Restrict the provider attribute condition to repository Jezang/wishing-christmas and ref refs/heads/main. Prefer repository ID in the condition when configuring. Grant narrowly scoped Firebase Rules Admin and Cloud Datastore Index Admin roles and read-only project metadata permissions needed by CLI; never Owner/Editor or student-data write access.
3. In GitHub Settings > Secrets and variables > Actions > Variables add FIREBASE_WIF_PROVIDER (full resource name projects/NUMBER/locations/global/workloadIdentityPools/POOL/providers/PROVIDER) and FIREBASE_DEPLOY_SA (service account email). No private key is required. Leave FIREBASE_AUTO_DEPLOY unset until manual deployment is verified.
4. In Actions > Deploy Firestore configuration > Run workflow select main. Review the run logs, confirm Rules are published, index board classroom ASC / xp DESC is Enabled, and test an anonymous student and teacher in separate browsers.
5. Once verified, set FIREBASE_AUTO_DEPLOY=true. Subsequent changes to rules, indexes or configuration merged to main trigger deployment. If deployment fails, inspect logs; do not force-delete indexes. Roll back by reverting the relevant rules change and re-running after review.
6. Sign in as teacher and use Game Manager to set round and enable score submissions. This is a separate teacher decision, not an automatic data write.
## Security
Do not paste Google service account keys, passwords or access tokens in chat or commit them. Workload Identity Federation uses short-lived credentials. The workflow deliberately stays disabled for automatic push deployments until explicitly configured. GitHub Pages deployment remains separate. Initial production state and credentials have not been verified by this chat.
Reference: https://github.com/google-github-actions/auth and https://firebase.google.com/docs/rules/manage-deploy
